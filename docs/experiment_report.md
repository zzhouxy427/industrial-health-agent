# FD001 实验报告

## 1. 目的与数据

本实验以 NASA C-MAPSS 的 FD001 仿真数据为对象，目标是根据运行周期、3 个运行设置和 21 个传感器读数，预测每台发动机的剩余寿命（RUL）。FD001 为单一工况、单一故障模式的仿真基准，因此适合验证工程工作流，但不能代表真实设备的全部复杂性。

## 2. 模型与特征

- 模型：`RandomForestRegressor`。
- 模型版本：`rf-fd001-raw-conformal-v3`。每次诊断的结构化上下文和审计日志均记录此版本、特征集、超参数与评估摘要。
- 选择参数：`n_estimators=200`、`max_depth=20`、`min_samples_leaf=4`、`max_features=1.0`、`random_state=42`。
- 特征：周期、3 个运行设置、21 个传感器原始读数。原始特征由发动机级 5 折交叉验证从多个滚动窗口方案中选出，统一定义在 `feature_config.py`；窗口对比见 [temporal_feature_selection.md](temporal_feature_selection.md)。
- 输出：RUL 点预测；并利用每棵树的输出计算 P10/P90 经验区间和标准差。区间通过训练集独立发动机的 split conformal 偏移扩张，RUL 下界按物理约束截断为 0。

## 3. 验证方法

### 3.1 发动机级 5 折交叉验证

使用 `GroupKFold`，以 `unit_number` 作为分组。同一台发动机的所有周期只会出现于训练折或验证折之一，从而降低同一轨迹泄漏到验证集的风险。

当前代码在本地重新运行 `python src\cross_validate_model.py` 的结果：

| 折数 | MAE（cycles） | RMSE（cycles） |
| --- | ---: | ---: |
| 1 | 27.25 | 40.73 |
| 2 | 25.96 | 38.65 |
| 3 | 25.25 | 36.06 |
| 4 | 28.75 | 38.80 |
| 5 | 24.67 | 33.61 |
| 汇总 | **26.37 ± 1.64** | **37.57 ± 2.77** |

### 3.2 官方测试集评估

模型在训练集全部样本上训练后，仅对官方测试集每台发动机的最后一个观测周期预测，并与 `RUL_FD001.txt` 对比。

| 指标 | 结果 |
| --- | ---: |
| 发动机数 | 100 |
| MAE | **19.53 cycles** |
| RMSE | **26.10 cycles** |

结果可通过 `python src\evaluate_official_test.py` 复现。不同平台、依赖版本或并行实现可能造成末位的轻微差异；报告中的数值以当前代码和环境的实际输出为准。

### 3.3 Split conformal 预测区间覆盖率

对每台测试发动机，先收集随机森林中各树的预测，并取 P10–P90 形成名义约 80% 的基础区间。随后，按发动机划分训练数据：前 80 台用于拟合模型，后 20 台作为独立校准集；每台校准发动机在 50%、70%、85%、95% 生命周期位置各取一个因果观测点，共 80 个校准点。使用 split conformal 有限样本分位数估计 6.33 cycles 的双侧扩张偏移，RUL 下界按物理约束截断为 0。官方测试标签不参与该校准。通过 `python src\evaluate_prediction_intervals.py` 在官方测试集上评估：

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 100 |
| 实际覆盖率 | **86.0%** |
| 平均区间宽度 | 76.69 cycles |
| 真实 RUL 低于下界 | 11 台 |
| 真实 RUL 高于上界 | 3 台 |

实际覆盖率高于名义 80%，说明本次独立校准在 FD001 测试集上偏保守，代价是区间更宽。它仍是单个模拟基准上的经验结果，不能解释为真实设备上的严格安全保证；后续应在跨工况、跨设备的独立数据上重复校验。

### 3.4 人工复核告警提前量回测

仅报告“预测是否准确”不足以说明诊断工作流是否有运维价值。为测试风险队列能否在真实 RUL 进入 20-cycle 临界区前提示人工复核，使用前 64 台发动机拟合随机森林、随后 16 台发动机校准预测区间、最后 20 台发动机进行时序回测。对每台留出发动机，按照运行周期从早到晚查找首次满足校准后 P10 ≤ 20 的时刻；整个过程不使用未来周期或官方测试标签。

| 指标 | 结果 |
| --- | ---: |
| 留出发动机数 | 20 |
| 触发人工复核 | 20 台 |
| 未触发人工复核 | 0 台 |
| 临界区前触发复核 | 19 台 |
| 提前告警中位提前量 | 21.5 cycles |

结果可由 `python src\evaluate_alert_timing.py` 复现，明细保存为 `artifacts/alert_timing_backtest.csv`。这些数字仅说明 FD001 模拟数据上的回测表现：预警意味着进入人工复核流程，而非自动停机、维修或对真实设备告警时限的承诺。

### 3.5 输入分布漂移压力测试

为验证 PSI 监控机制对受控输入变化的敏感性，复制 FD001 测试批次并在不修改原始文件的条件下，分别对 `sensor_4`、`sensor_11` 和 `op_setting_1` 注入训练集标准差 3 倍的加性偏移。该测试不用于模拟真实故障，也不将 PSI 视为准确率下降的直接证据；它只验证统计监控能否将显式注入的输入偏置标识为人工复核信号。

| 场景 | 注入特征 PSI | 监控告警 |
| --- | ---: | --- |
| `sensor_4_calibration_offset` | 9.713 | 是 |
| `sensor_11_calibration_offset` | 9.790 | 是 |
| `op_setting_1_operating_shift` | 6.756 | 是 |

结果可由 `python src\drift_stress_test.py` 复现，完整产物位于 `artifacts/drift_stress_test.md`。受控场景中原始测试批次本身也存在分布偏移，因此应比较注入特征的 PSI 与最高偏移特征，而不是把“是否告警”误读为模型是否失效。

### 3.6 性能发布门禁

完整流水线会在生成官方测试评估后，将本次 MAE/RMSE 与版本化的性能门限比较。当前门限在既有基线（MAE 19.53、RMSE 26.10）基础上保留合理波动空间：MAE 不得超过 22.00 cycles，RMSE 不得超过 30.00 cycles。当前版本结果如下：

| 指标 | 当前结果 | 门限 | 结果 |
| --- | ---: | ---: | --- |
| MAE | 19.53 | 22.00 | 通过 |
| RMSE | 26.10 | 30.00 | 通过 |

门禁命令为 `python src\performance_gate.py`，依赖由 `evaluate_official_test.py` 导出的 `artifacts/official_evaluation.json`。由于原始 FD001 数据不会提交到仓库，GitHub Actions 验证门禁规则的单元测试；有数据的本地完整流水线执行真实指标门禁。门禁通过不意味着模型适用于真实生产环境，也不替代跨数据集评估和领域专家审核。

### 3.7 风险队列离线评估

风险队列本身也需要作为一个决策策略被单独评估。在官方测试集的离线实验中，以真实 RUL ≤ 20 cycles 作为“临界状态”标签；运行时不使用这一标签，它只用于事后测量。比较仅依赖点预测的 `critical` 策略，与将区间下界触及阈值的设备也纳入 `review` 的人工复核策略：

| 策略 | 精确率 | 召回率 | TP | FP | FN | TN |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 仅 `critical` 点预测 | 90.9% | 62.5% | 10 | 1 | 6 | 83 |
| `critical` + `review` 人工复核队列 | 71.4% | 93.8% | 15 | 6 | 1 | 78 |

区间感知的队列以额外 5 个误报为代价，将漏报从 6 台降低到 1 台，符合本原型“优先安排人工复核、而非自动执行维护”的定位。结果可由 `python src\evaluate_risk_queue.py` 复现，输出保存到 `artifacts/risk_queue_evaluation.md`。该离线指标不等价于真实业务中的告警性能，真实部署仍需结合可用人力、设备成本、提前量需求和领域专家意见重新校准。

## 4. 风险阈值校准

在编号 1–80 的发动机训练、81–100 的发动机验证设置中，模拟 50%、70%、85%、95% 四个观测时刻。漏报成本设为误报的 5 倍：

`risk_cost = 5 × false_negative + false_positive`

| 阈值 | 漏报 | 误报 | 风险成本 |
| ---: | ---: | ---: | ---: |
| 20 | 3 | 1 | **16** |
| 30 | 6 | 1 | 31 |
| 40 | 7 | 2 | 37 |
| 10 | 7 | 3 | 38 |
| 50 | 9 | 3 | 48 |

因此当前原型采用 **20 cycles** 作为风险阈值。该选择体现的是本实验中设定的成本偏好，不是现实设备的通用维护规范。

## 5. 诊断工作流评估

模型预测不会单独决定结论，而是与以下证据一起进入人工复核流程：

1. 校准后 P10/P90 区间：区间下界触及风险阈值时进入 `review` 队列；告警提前量在留出发动机历史中单独回测。
2. 数据质量：检查缺失、重复周期、周期间断和训练集 1%–99% 范围提示。
3. PSI 输入漂移：当当前批次多个特征与训练集分布显著偏移时，提示复核模型适用范围。
4. 关键传感器趋势：sensor_4 与 sensor_11 同时上升时提高人工复核优先级。
5. 本地知识库和可选 LLM：只解释已有结构化证据；LLM 文本必须通过安全检查。

## 6. 可复现步骤

在原始 FD001 文件放入 `data/raw/` 后，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_full_pipeline.ps1
```

该入口会重新生成预测、官方评估、数据漂移报告、风险队列、批量复核摘要，并运行测试。原始数据和运行产物均不提交到 Git。

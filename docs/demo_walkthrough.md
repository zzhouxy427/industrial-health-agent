# 3 分钟项目演示脚本

本文用于本地演示“工业健康代理人”。演示目标不是声称模型可以替代真实维护决策，而是清楚展示：项目如何把 RUL 预测、不确定性、数据质量、分布漂移、人工复核和受限 LLM 串成一个可追溯的诊断流程。

## 0. 演示前准备

在项目根目录打开 PowerShell：

```powershell
cd "E:\agent-project"
.\.venv\Scripts\Activate.ps1
streamlit run src\dashboard.py
```

浏览器打开 `http://localhost:8501`。如果需要从原始数据完整复现结果，先执行：

```powershell
.\scripts\run_full_pipeline.ps1
```

## 1. 开场：问题与边界（约 20 秒）

可以这样介绍：

> 这是一个基于 NASA C-MAPSS FD001 的工业设备健康诊断 Agent 原型。它预测发动机剩余寿命，同时将预测区间、数据质量、数据分布漂移和传感器趋势用于人工复核排序。它是研究与决策辅助工具，不会自动下达停机、维修或其他安全关键指令。

要点：FD001 是公开仿真基准；项目结论不等同于真实航空维修结论。

## 2. 首页：先看批次风险（约 35 秒）

展示“运行状态总览”四个指标：

1. **纳入监测设备**：当前批次规模。
2. **优先人工复核**：点预测 RUL 已低于 20 周期阈值的设备数。
3. **区间复核**：点预测尚未触线，但 80% 预测区间下界触及阈值的设备数。
4. **显著输入偏移特征**：当前测试批次与训练数据存在明显分布差异的特征数。

建议讲法：

> 系统不把“低风险”理解为“没有风险”。若输入分布发生偏移，或传感器趋势异常，页面会明确提示人工复核。这是为了避免把模型分数直接当作维护命令。

## 3. 风险队列：解释排序逻辑（约 35 秒）

展开“查看批量人工复核队列”。重点介绍三个字段：

- `predicted_rul`：随机森林点预测的剩余寿命。
- `prediction_p10` / `prediction_p90`：从森林中各棵树预测得到的经验 80% 区间。
- `priority`：`critical`、`review` 或 `monitor`。

排序规则：

| 优先级 | 触发条件 | 含义 |
| --- | --- | --- |
| `critical` | 点预测 RUL ≤ 20 | 优先人工复核 |
| `review` | 点预测高于 20，但 P10 ≤ 20 | 不确定性可能触线，建议复核 |
| `monitor` | 其余设备 | 继续监控 |

强调：队列是在分配人工注意力，不是自动维护指令。

## 4. 单台诊断：以发动机 34 为例（约 45 秒）

在左侧选择发动机 `34`。它通常位于队列前部，适合作为高风险示例。展示：

1. 点预测 RUL 与 80% 预测区间；
2. 风险阈值与当前队列优先级；
3. `sensor_4`、`sensor_11` 的近期趋势；
4. 数据质量状态；
5. 本地知识库检索到的维护建议。

建议讲法：

> 这里的报告同时保留了“模型认为还剩多少周期”和“预测的不确定范围”。如果趋势、输入漂移或数据质量与模型结论存在冲突，系统提升人工复核优先级，而不是自行做出停机或维修动作。

## 5. LLM 辅助诊断：受限工具调用（约 25 秒，可选）

只有配置了本地 `.env` 中的 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL` 时，才点击“生成 LLM 辅助诊断”。

展示前说明：

> LLM 只能读取导出的结构化上下文和知识库内容。输出会经过安全校验：必须包含预测区间、趋势与人工复核说明；若出现自动停机、立即维修等危险指令，会被拦截而不展示。

不要在演示、截图或 Git 提交中展示 API 密钥。

## 6. 收尾：可追溯性与验证（约 20 秒）

展示“近期诊断审计记录”，然后在终端运行：

```powershell
python -m pytest -q
python src\evaluate_official_test.py
```

可以这样收尾：

> 这个项目的价值不只是一条 RUL 预测，而是将模型、预测区间、数据健康、人工复核和审计记录组合为可复现的工程流程。目前测试覆盖核心规则；未来会继续扩展多工况数据、时序模型、校准方法和真实运维场景的评估。

## 面试追问速答

**为什么按发动机而不是随机按行切分？**  
同一发动机的相邻周期高度相关；随机按行切分会造成信息泄漏，得到过于乐观的指标。因此交叉验证与训练/验证拆分以发动机为单位。

**为什么既有点预测又有预测区间？**  
点预测无法表达模型内部的不确定性。区间下界触线时，即使点预测尚未触线，也进入人工复核队列。

**为什么要做数据漂移和质量检查？**  
真实输入可能与训练数据不同，也可能存在缺失、重复、周期异常。预测输出只有在输入质量可接受、适用性提示被人工理解的情况下才有参考意义。

**LLM 在系统里做什么？**  
只做受约束的解释与总结，不能改写数值、不能虚构证据、不能自动控制设备。规则和安全校验仍由确定性代码负责。

# 简历项目描述与面试讲解稿

## 一、简历项目名称

工业健康 Agent：面向预测性维护的剩余寿命预测与风险诊断系统

## 二、简历精简版

**工业健康 Agent｜Python、scikit-learn、Pandas、Streamlit、LLM API**

- 基于 C-MAPSS FD001 构建发动机剩余寿命（RUL）预测与维护诊断原型，完成数据处理、Random Forest 建模、预测区间、风险队列和 Streamlit Dashboard 的端到端流程。
- 使用发动机级 GroupKFold 交叉验证避免同一设备轨迹泄漏；官方 FD001 测试集 MAE 为 19.53 cycles，RMSE 为 26.10 cycles，5 折交叉验证 MAE 为 26.37 ± 1.64 cycles。
- 引入 P10–P90 预测区间、风险阈值和 `critical/review/monitor` 优先级队列，将模型输出转化为人工复核任务，并通过数据质量检查、PSI 漂移分析和模型发布门禁降低错误使用风险。
- 集成可选 LLM 辅助诊断，使用结构化上下文和输出安全校验限制自动停机、维修等危险指令；实现审计日志、模型快照完整性检查和 42 项自动化测试。

## 三、简历详细版

开发工业设备健康 Agent 原型，面向发动机预测性维护场景，将 RUL 预测、预测不确定性、传感器趋势、维护知识检索和 LLM 辅助解释串联为可追溯诊断流程。针对时间序列数据按发动机分组进行训练/验证拆分，避免随机按行切分造成的信息泄漏；通过 Random Forest 树集合分位数和 split conformal 方法生成经验预测区间；依据点预测和区间下界构建风险队列，并使用离线标签评估漏报与误报权衡。系统同时包含数据质量门禁、输入分布漂移监控、审计记录、模型 SHA-256 快照校验、Streamlit 可视化和 LLM 输出安全校验。项目当前为仿真数据上的研究型原型，不宣称真实设备安全保证。

## 四、面试 60 秒版本

这是一个工业设备预测性维护 Agent。输入是发动机的历史传感器数据，系统先检查数据质量，再用 Random Forest 预测剩余寿命，并通过树集合分位数和 conformal 校准给出预测区间。随后根据预测值和区间下界把设备分为 critical、review 和 monitor 三类，生成需要人工复核的风险队列。Agent 还会结合传感器趋势和维护知识生成诊断说明，但 LLM 只负责解释，不执行停机或维修。为了保证可追溯性，我加入了数据质量检查、漂移监控、审计日志、模型快照校验和自动化测试。当前结果基于 C-MAPSS FD001 仿真数据，定位是研究和学习型原型。

## 五、面试 3 分钟版本结构

### 1. 为什么做这个项目

单独输出一个 RUL 数字不够支持维护决策，因为预测存在误差，传感器可能漂移，模型也可能与现场趋势不一致。因此项目目标不是自动控制设备，而是生成带不确定性和证据链的人工复核建议。

### 2. 系统流程

```text
历史传感器数据
    -> 数据质量检查
    -> 特征与 RUL 模型
    -> 预测区间
    -> 风险队列
    -> 传感器趋势与知识检索
    -> 可选 LLM 解释
    -> Dashboard 与审计日志
```

### 3. 最重要的工程取舍

- **按发动机分组验证**：同一发动机相邻周期高度相关，随机按行切分会造成数据泄漏，因此使用发动机级拆分和 GroupKFold。
- **输出区间而非单点**：维护人员需要知道预测的不确定性，所以同时展示点预测、P10–P90 区间和风险阈值。
- **优先人工复核而非自动动作**：风险队列的目标是降低漏报，不能把模型结果直接转化为停机或维修指令。
- **LLM 只做受限解释**：LLM 只能使用结构化上下文，输出经过安全校验，禁止自动停机、维修和安全关键命令。

### 4. 如何验证

- 官方 FD001 测试集：MAE 19.53 cycles，RMSE 26.10 cycles；
- 5 折发动机级交叉验证：MAE 26.37 ± 1.64 cycles；
- 自动化测试：42 passed；
- 发布审计：性能、风险队列和模型快照完整性门禁全部通过；
- Streamlit 页面验证了低风险、高风险、风险队列、LLM 安全校验和历史审计记录。

## 六、常见追问与回答

### 问：为什么不用随机切分？

因为同一发动机的相邻周期不是独立样本。随机切分会让训练集和验证集包含同一条退化轨迹，造成信息泄漏和过于乐观的指标，所以按发动机分组切分。

### 问：预测区间是不是安全保证？

不是。当前区间只是在 FD001 仿真数据上的经验覆盖率证据。它用于表达不确定性和帮助人工复核，不能替代真实设备验证、安全认证或工程师判断。

### 问：LLM 在系统中具体做什么？

LLM 根据预测 RUL、风险等级、传感器趋势和维护知识生成解释性诊断摘要。它不重新计算预测结果，也不执行控制动作；输出还要经过安全规则校验。

### 问：项目最大的不足是什么？

数据仍是 FD001 仿真数据，缺少真实设备工况、工业通信接入和线上长期运行验证。因此当前项目更准确的定位是工程化研究原型，而不是生产级预测性维护系统。

### 问：如果继续做，你会怎么扩展？

下一步会接入 MQTT 或 OPC UA 的实时数据模拟流，增加模型漂移后的再训练策略，并在更多工况或真实匿名数据上验证预测区间和风险队列的稳定性。

## 七、使用边界

简历和面试中可以强调“端到端工程能力、验证意识和安全边界”，但不要表述为：

- 已部署到真实航空发动机；
- 可以准确预测真实设备故障；
- LLM 可以自动进行维修决策；
- 预测区间提供安全保证。
